# 可复用的大模型协作技能包

本技能包面向Linux＋FPGA共享加速器，不绑定铝材类别或特定板号。它将真实开发中反复使用的判断、提示词与验收方法固化为可执行核查；不是安装了PYNQ，也不申报未经实现的PYNQ通用能力。提示词见 [prompt_workflows.md](prompt_workflows.md)，排查表见 [pitfalls.md](pitfalls.md)。

|技能名称|适用场景|使用方法|失效边界|提炼来源|验证效果|
|---|---|---|---|---|---|
|冻结配套硬件与数值契约|多个bit/模型/设备树并行研发|记录源提交、模型SHA、bit/XSA、DT、ABI后再比较|文件正确不证明当前板实际加载该bit|早期只换bit导致旧RTC通路失效；后续配套临时启动|本基线XSA内bit及服务清单一致，原实板输出通过|
|区分量化误差与电路错误|整数PL接FP32余网|先CPU整数oracle对PL逐值，再评估与FP32偏差|单图整数一致不能证明mAP无损|首层及各子图整数出口/尾网注入验收|原基线97报文、实板固定出口匹配；总体mAP未测|
|完整边界计时|新增层却无净收益|同bit/boot、CPU/线程固定，轮换7记录，每记录2预热，拆互斥阶段|不能跨轮、跨线程配置或把嵌套周期重复累加|PL30比PL21慢3.231ms的真实结果|完整记录保留，未把覆盖增长当提速|
|缓存生命周期预算|BRAM近满、共享PE|列生产者、最后消费者、地址区间、覆盖顺序，再写RTL|容量够不表示端口、时序或原语映射足够|C6/C11/C21片上交接与长期skip|72块特征RAM复用，原始132.5等效报告可追溯|
|时序证据分级|OOC/布局/全系统报告结论冲突|分别列输入/内部路径及阶段，完整setup/hold/coverage签核|仿真、布局估计和某类路径通过不代表最终STA通过|接口保持诊断、完整集成及postroute修复|本基线100MHz建立/保持和12类检查通过|
|可移植提交校验|从开发仓库整理参赛版|运行verify_submission.py，核对命名、来源与全部清单|SHA绑定不替代执行新综合、硬件测试或授权审查|本次独立整理及真实部署包漏清单修复|已知SHA、字节篡改、路径越界与完整提交均可检查|

**PowerShell或Bash，在仓库根目录：**

```text
python -B skill/verify_submission.py
```

仅只读检查，默认定位本仓库；`--root`可指定另一份相同格式提交。失败输出具体路径并返回非零，不静默补造文件或数据。其他项目可以复用 `check_hashes(root, entries)`，但硬件身份、目录规范、资源阈值和数值契约必须换成项目自己的事实。

固定输入的实板结果下载后，**PowerShell 或 Bash，在仓库根目录执行：**

```text
python -B skill/verify_submission.py --results D:/FPGA_AMD_Zynq_results/pl30_check --backend pl30
```

`--results` 为实际结果目录；`--backend pl30` 校验三个 INT8 出口、尾网输出及事务报告。CPU 固定输入输出使用 `--backend cpu`，与独立 CPU 黄金参考比较。该功能只读文件，不执行推理。真实 PL30 归档结果已验证通过，改变 C30 一个字节会被拒绝；不能用于不同输入、模型或量化方案。

已知跨场景可复用的是文件绑定/计时方法和提示词结构；**尚未在另一块板或另一支队伍的干净环境独立验证**，不虚构跨设备迁移成功率。
